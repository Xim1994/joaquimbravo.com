Decisions scope & consequence

Built the monitoring platform instead of buying it

Off-the-shelf tools gave no per-client portal with scoped access, and could not carry the energy-anomaly logic the business actually sells. Built in-house as multi-tenant software with audit logs and encrypted tokens — monitoring went from a cost to something we charge for.

Productized the installation instead of quoting bespoke

Every quote was a one-off, so delivery depended on me being in the room. Replaced it with closed packages, a device catalogue as the single source of truth and a dashboard generator fed from it — the team now delivers installations without me.

Wrote the build / integrate / ignore rule before building anything

The failure mode of an engineer-led company is rebuilding software that already exists, now that it is cheap to. Formalized a written gate applied before every project — build only what gains from owned data, wrap by API what the market solves, ignore commodities — so features get killed before they become debt.

Separated who produces from who verifies

A self-reported “done” is not evidence. Automated work runs behind an adversarial verifier with measurable stop conditions, hard caps, spend limits and a provider fallback chain — false claims get caught by machine, and the system keeps working when the main provider runs out.

Decisiones alcance y consecuencia

Construir la plataforma de monitorización en vez de comprarla

Lo que había en el mercado no daba a cada cliente su portal con acceso limitado, ni la lógica de anomalías de energía que es justo lo que vendemos. Se construyó dentro, multi-tenant, con auditoría y tokens cifrados — y la monitorización pasó de coste a algo que se cobra.

Productizar la instalación en vez de presupuestar a medida

Cada presupuesto era un traje hecho a mano, así que la entrega dependía de que yo estuviera delante. Se sustituyó por paquetes cerrados, un catálogo de aparatos como fuente única y un generador de dashboards — ahora las instalaciones las entrega el equipo sin mí.

Escribir la regla construir / integrar / ignorar antes de construir nada

La forma de fallar de una empresa de ingenieros es rehacer software que ya existe, ahora que sale barato. Se formalizó un filtro escrito previo a cada proyecto — construir solo lo que gana con datos propios, envolver por API lo que el mercado resuelve, ignorar lo commodity — y las funcionalidades se descartan antes de ser deuda.

Separar a quien produce de quien verifica

Un «hecho» dicho por quien lo hizo no es evidencia. El trabajo automatizado pasa por un verificador adversarial con parada medible, topes duros, límite de gasto y cascada de respaldo entre proveedores — las afirmaciones falsas las caza una máquina y el sistema sigue cuando se agota el proveedor principal.
